# Reflexión

## ¿A qué tipo de audiencia o trabajo está dirigido este portafolio?

Este portafolio está dirigido principalmente a empresas tecnológicas, startups SaaS y equipos de desarrollo que valoran el backend, el diseño de bases de datos y la construcción de sistemas orientados a procesos de negocio.

Al planificar el proyecto decidí enfocarme en el tipo de trabajo que me gustaría desempeñar profesionalmente en el futuro. Mi interés principal se encuentra en el desarrollo backend, la arquitectura de software y el diseño de bases de datos, por lo que quise que el portafolio transmitiera una imagen coherente con ese perfil.

En lugar de presentar una colección de tecnologías o proyectos sin relación entre sí, busqué construir una narrativa consistente que mostrara cómo utilizo la programación para resolver problemas reales mediante sistemas de información, gestión de datos y aplicaciones empresariales.

La audiencia ideal para este portafolio serían empresas que buscan desarrolladores capaces de comprender tanto la lógica de negocio como la estructura técnica necesaria para construir aplicaciones mantenibles y escalables.

---

## ¿Qué tecnologías eligieron usar y por qué?

Para el desarrollo del portafolio elegí utilizar React, Vite y Tailwind CSS.

React fue seleccionado porque permite construir interfaces modernas mediante componentes reutilizables, facilitando la organización del proyecto y la escalabilidad del código.

Vite fue utilizado debido a su rapidez durante el desarrollo y simplicidad de configuración, permitiendo concentrarme en la construcción del producto sin invertir tiempo adicional en herramientas complejas.

Tailwind CSS fue elegido porque ofrece una forma eficiente de diseñar interfaces modernas y responsivas manteniendo consistencia visual en toda la aplicación.

Además, decidí implementar funcionalidades como modo oscuro/claro y filtrado dinámico de proyectos para mejorar la experiencia de usuario sin comprometer la simplicidad del sitio.

La combinación de estas tecnologías me permitió construir un portafolio profesional, rápido y alineado con las prácticas actuales del desarrollo web moderno.

---

## ¿Qué tecnología del curso decidieron no usar y por qué?

Una de las tecnologías que decidí no utilizar fue JavaScript Vanilla.

Aunque tengo experiencia utilizándolo en proyectos anteriores y fue una parte importante de los temas vistos durante el curso, consideré que React era una mejor opción para este proyecto debido a la cantidad de componentes, secciones y funcionalidades que debía implementar.

Utilizar React permitió mantener una estructura más organizada, reutilizar componentes y facilitar futuras modificaciones al portafolio.

La decisión no fue porque JavaScript Vanilla fuera insuficiente, sino porque React ofrecía ventajas más adecuadas para los objetivos específicos del proyecto y para el tipo de aplicaciones web modernas que me interesa desarrollar profesionalmente.

---

## ¿Dónde se arriesgaron y dónde la jugaron seguro? ¿Por qué tomaron esa decisión en cada caso?

La parte donde decidí arriesgarme fue en la definición de la audiencia y en el enfoque general del portafolio.

En lugar de crear un portafolio genérico mostrando todas las tecnologías y proyectos posibles, opté por construir una identidad clara orientada al backend y las bases de datos. Esto implicó seleccionar cuidadosamente los proyectos presentados y priorizar aquellos que demostraban arquitectura de software, modelado de datos y resolución de problemas empresariales.

También decidí implementar funcionalidades adicionales como el modo oscuro/claro y el filtrado dinámico de proyectos para mejorar la experiencia del usuario.

Por otro lado, decidí jugar seguro en las tecnologías principales utilizadas para construir el portafolio. React, Vite y Tailwind CSS son herramientas que ya conocía y con las que tenía experiencia previa. Esto me permitió concentrar el esfuerzo en la calidad del diseño, la organización del contenido y la presentación profesional del proyecto en lugar de invertir tiempo aprendiendo nuevas herramientas durante el desarrollo.


---

## Si tuvieran otra semana, ¿qué mejorarían?

Si dispusiera de una semana adicional, me gustaría incorporar características más avanzadas relacionadas con visualización de datos e inteligencia artificial.

Una mejora interesante sería desarrollar una sección interactiva donde los visitantes pudieran explorar con mayor detalle la arquitectura de mis proyectos, los modelos de datos utilizados y las decisiones técnicas tomadas durante el desarrollo.

También me gustaría experimentar con herramientas de inteligencia artificial para generar explicaciones dinámicas de los proyectos o asistentes que permitieran navegar el contenido de forma más personalizada.

Además, aprovecharía ese tiempo para documentar con mayor profundidad cada proyecto, agregando diagramas de arquitectura, modelos entidad-relación y detalles técnicos que permitieran mostrar mejor mi interés por el diseño de bases de datos y la ingeniería de software.
